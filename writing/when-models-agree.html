When two models agree on the wrong number

A battery-storage project consultancy needed the results of supplier factory test reports pulled into Excel. One supplier's reports are 12-page scans. Inspectors write the values by hand: insulation resistance, charge and discharge energy, round-trip efficiency. Red stamps land on top of the numbers, and the table lines are faint.

The client wanted the values that need a human to be clearly marked. I turned that into one target: zero silent errors. A flagged error costs someone a quick check. An unflagged one can end up in an engineering decision.

The baseline

I started with an answer key: 90 values from six trial reports, reconciled by independent AI readers and blind judges. Against it, conventional OCR (PyMuPDF plus Tesseract) got 14 of 90 right. Claude Opus 5 reading the page images got 86. One strong reader did well on six reports. Across 71, the harder problem was knowing which answers to trust.

In a smoke test, the cheapest model read 36700 as 3670 and reported 0.98 confidence.

Evidence instead of confidence

The pipeline finds each page by its content rather than its page number, since pages go missing, repeat or come in rotated. It cuts every value cell out of the table grid and reads each page twice: once whole, once as close-ups of the cells. A value is accepted when one of these holds:

  • the written round-trip efficiency matches 100 × discharge ÷ charge energy within 0.006 points, so the handwriting is checked against its own arithmetic;
  • a typed serial number matches the OCR text or the file name;
  • the whole-page read and the close-up read agree. In the delivered run both reads came from OpenAI models, so this rule was itself same-family agreement, and the next version replaces it;
  • it is printed text, a tick box or the reviewer's name, read at 0.9 confidence or above.

Everything else is flagged. When the efficiency check fails, a repair step looks for the combination of candidate readings that makes the maths work with the fewest changes. If two combinations tie, it flags the value instead of choosing. The overall pass or fail comes from OCR of the printed table, because a model once turned a passing report into "Fail"; the model's read is used only when OCR can't read the table. I also tried majority voting between reads and removed it, because two reads agreed on wrong values.

On the trial reports, with Claude Opus 5 reading, this reached 87 of 90, with the other 3 flagged and no silent errors.

What each pass did in the delivered run

The delivered run used OpenAI models for both reads. The main run covered 69 of 71 reports, read 1,932 values, flagged 405 and cost $28.04. The passes after it were measured against the same 90 verified values:

StageCorrectWrong, flaggedWrong, silent
Main run75150
+ third read of the same crop, same model75150
+ re-read of the full table row, same family7875
+ Claude Opus 5 on every flag8532

The full-row read helped. Seeing the code, requirement, units and handwriting together corrected values that a zoomed crop couldn't. But clearing a flag because it now agreed with an earlier read from the same model family produced 5 silent errors, where there had been none. In a later benchmark, accepting whenever the two OpenAI readers agreed would have accepted 74 cells, 8 of them wrong.

A reader from a different vendor fixed most of it. The Claude Opus 5 pass re-checked 1,159 values, settled 1,078 and corrected 92, for $16.34. An Opus 5.5 pass on what was still flagged settled 97 of 126 and corrected 52, for $1.56.

Where it ended

After those passes the verified sample stood at 87 of 90, the same as the trial, but 2 of the 3 misses were silent: 1400 read for 14100 and 0.02 for 0.022. Every reader made the same misreading. Those cells were corrected from the answer key. All but 3 of the last 102 flags were settled before delivery; those 3 are on a page missing from one report. Most were one reviewer's signature, which was standardised. Each of the 32 real values was read by two blind AI readers zooming into the scan, with a judge where they disagreed. The delivered workbook has 71 reports and 1,988 values.

A range scan and a check for reader disagreement then surfaced 7 suspect values. Blind AI review found 3 were our misreads, now fixed, and 4 were written that way on the reports, outside the form's own limits.

What remains: on reports without verified values, expect a few percent of handwritten values to be misread in a way every reader agreed on. Of the 66 verified handwritten values, 2 were.

The next version

Reading whole pages is most of the cost, yet free OCR already finds every value cell. So I built a benchmark of 923 cell images and 1,207 values to choose readers for a cell-only version. Only 54 cells are verified gold; the rest are labelled with delivered values, which favours readers that agree with the pipeline. On a stratified 119-cell sample (151 values, 66 gold), single-reader accuracy was as below. The tool now runs on OpenAI only, so the Claude rows are for reference.

Telling the model each cell's unit and how the form writes its numbers took GPT-5.6 sol to 88.7% in a later run. The design I'm testing chains a free OCR engine, a cheap model and sol, and calls sol only where the first two disagree. On the sample it auto-accepted 80% of cells (95 of 119) with none wrong, at about $0.03 per report at batch prices for this first pass, or about $0.06 live. The delivered run's main pass cost about $0.41 per report. Zero wrong in 95 accepted cells still allows up to about 3% true error, so it needs a larger sample before anyone relies on it.

What I took from it

  • Count silent errors separately from flagged ones. A single accuracy number hides them.
  • When two reads from one model family agree, they often share the same mistake, so their agreement is weak evidence. Agreement counts for more when the readers can fail in different ways.
  • The strongest checks come from the document itself: arithmetic that has to balance, serials that have to match. They are free and don't share a model's blind spots.
  • Not every report needed AI. The other supplier's reports are digital, and a deterministic parser read 153 of them, 22,950 measurements, with no parse failures and no model cost.
