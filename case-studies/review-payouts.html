Problem

Staff earn a bonus for each patient review they bring in and text a screenshot as proof. One person read every screenshot by eye and typed rows into about 60 separate Google Sheets. The client put it at 4 to 6 hours a month, with recurring errors: reviews credited to the wrong facility, skipped threads, underpaid staff.

How it works

Messages come in through the Gmail API. Spam and filler are removed by plain rules before any model is called. Each image is cleaned up, then read by Claude Vision into structured JSON, with a smaller model as fallback. The sender's number is matched to a staff record and the pay rules and monthly cap are applied. Repeat submissions of the same review on the same day are merged, keeping the higher payout.

Pipeline stages, in order:

  1. Pull texts
  2. Filter noise
  3. Read screenshot
  4. Match staff
  5. Apply pay rules
  6. Merge repeats
  7. Write sheets

What it guards against

Accusing staff of fake reviews. Google's API returns at most five reviews per listing, so a review it can't find proves nothing. A review is flagged only when the visible window of every listing that loaded covers its date. In four months that flagged 3 of 247 Google reviews. In one month every lookup was rejected because of a key restriction, and the run marked reviews "can't confirm" instead of flagging anyone.

How I know it works

Dry run is the default, commits go to a sandbox sheet first, and the dashboard asks for a typed CONFIRM before a live write. So far it has only run as a dry run. There is no labelled set yet, so I don't quote an accuracy figure.

Stack

Python, Claude Vision, Gmail API, Google Sheets API, Google Places API, FastAPI.
